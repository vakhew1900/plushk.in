# configs

Тестовые наборы данных для ручной/автоматической проверки импорта/экспорта настроек (`SettingsExportImportService`, см. `specs/changelog.md` → `SETTINGS-1`). В будущем сюда же могут добавляться не только тестовые, но и реальные пользовательские наборы — папка не привязана к тестовому назначению структурно.

Каждый набор — отдельная подпапка с `settings.json`, валидным по форме `SettingsExport` (`src/types/settings-export.ts`): `version`, `exportedAt`, `rules`, `domainAliases`, `pageMatchGroups`, и опционально `tags`/`entityTypes` (добавлены в `SEARCH-6` — теги и категории, на которые может ссылаться правило через `BookmarkRule.tagIds`/`entityTypeId`; отсутствие поля равносильно пустому списку, старые файлы без него по-прежнему валидны). Файл можно скормить напрямую в диалог импорта настроек в UI (вкладка «Главная» → Export/Import) или в `SettingsExportImportService.importSettings`.

## Наборы

- **`mail/`** — почтовые сервисы (Gmail, Mail.ru, Yandex, Yahoo). Только матчинг по домену, без фильтрации по заголовку.
- **`it/`** — Habr/dev.to/O'Reilly: три правила, демонстрирующие связку правило → теги/категория (`SEARCH-6`). Два правила на доменах Habr/dev.to с разным набором слов в заголовке (регэксп с границами слова `\b...\b`, чтобы не ловить слово как часть другого — например «IT» не матчит «split») подсказывают теги `java`/`it`/`habr` и категорию «Статья», ведя в `IT/Java`/`IT/General`; третье — простое доменное правило на `www.oreilly.com` — подсказывает категорию «Книга» (без workflow/статусов — валидное состояние по `SHELF-1`), ведя в `IT/Books`.
- **`social-extras/`** — Reddit/DTF: демонстрирует `PageMatchGroup` (CSS-селекторы, реально проверенные на живой разметке `old.reddit.com` и `dtf.ru`) и правила, матчащие по `extras`-полям (`subreddit`, `hub`), которые эти селекторы должны заполнять.

## Известные ограничения (на момент создания наборов)

- **`domainAliases` не резолвятся движком правил.** `rule-evaluator.ts` не знает о `DomainAlias` — алиасы существуют только как отдельная сущность (UI вкладки «Алиасы» + экспорт/импорт). Поэтому во всех наборах домены в `rules[].condition` и в `domainAliases[].domain_names` продублированы вручную. См. задачу на резолвинг алиасов в правилах в `specs/backlog.md`.
- **`social-extras/` не сработает на живых закладках.** `PageExtractorService`/`PageMatchGroup` — рабочая инфраструктура извлечения `extras` со страницы, но она нигде не вызывается в реальном flow создания закладки (`background.ts` использует только `PageMetaFiller`, который не ходит на страницу; `content.ts` — заглушка). Файл валиден для импорта/экспорта и годится как фикстура на будущее, но правила `test-social-reddit-programming`/`test-social-dtf-games` не найдут совпадения, пока это не подключено. См. задачу на подключение `PageMatchGroup` к реальному flow в `specs/backlog.md`.
- Селектор `h1.redditname a` в `social-extras/` проверен на классической разметке `old.reddit.com`; современный `www.reddit.com` рендерит контент через веб-компоненты (`shreddit-post` и т.п.) с другой структурой DOM — селектор рассчитан именно на `old.reddit.com`-стиль страниц.
