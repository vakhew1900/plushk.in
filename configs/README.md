# configs

Тестовые наборы данных для ручной/автоматической проверки импорта/экспорта настроек (`SettingsExportImportService`, см. `specs/changelog.md` → `SETTINGS-1`). В будущем сюда же могут добавляться не только тестовые, но и реальные пользовательские наборы — папка не привязана к тестовому назначению структурно.

Каждый набор — отдельная подпапка с `settings.json`, валидным по форме `SettingsExport` (`src/types/settings-export.ts`): `version`, `exportedAt`, `rules`, `domainAliases`, `pageMatchGroups`, и опционально `tags`/`entityTypes` (добавлены в `SEARCH-6` — теги и категории, на которые может ссылаться правило через `BookmarkRule.tagIds`/`entityTypeId`; отсутствие поля равносильно пустому списку, старые файлы без него по-прежнему валидны) и `iconRules` (добавлено в `RULE-13` — правила источника иконки закладки; `IconBookmark`, кэш уже вычисленной иконки на конкретную закладку, в экспорт/импорт намеренно не входит — это per-bookmark инстанс-данные, а не переносимые настройки, как и `BookmarkTagLink`/`BookmarkEntityLink`). Файл можно скормить напрямую в диалог импорта настроек в UI (вкладка «Главная» → Export/Import) или в `SettingsExportImportService.importSettings`.

## Наборы

- **`mail/`** — почтовые сервисы (Gmail, Mail.ru, Yandex, Yahoo). Только матчинг по домену, без фильтрации по заголовку.
- **`it/`** — Habr/dev.to/O'Reilly: семь правил, демонстрирующие связку правило → теги/категория (`SEARCH-6`) **и** иерархию правил (`RULE-10`). `test-it-habr` — родительское правило на домене habr.com; четыре его потомка (`test-it-java`/`test-it-llm`/`test-it-python`/`test-it-rust`, siblings друг друга) каждый сужает только по своему слову в заголовке (регэксп с границами слова `\b...\b`), не повторяя проверку домена родителя, и полностью переопределяют `targetFolder`/теги/категорию (в дереве наследуется только `condition`) — ведут в `IT/Java`/`IT/LLM`/`IT/Python`/`IT/Rust`; сам родитель — запасной вариант `IT`, если заголовок не подошёл ни под одно из четырёх слов. `test-it-devto` и `test-it-book` — независимые (без `parentId`) простые доменные правила (dev.to и `www.oreilly.com`), наглядно показывающие, что обычные правила без вложенности продолжают работать как раньше; `test-it-book` дополнительно подсказывает категорию «Книга» (без workflow/статусов — валидное состояние по `SHELF-1`).
- **`social-extras/`** — Reddit/DTF: демонстрирует `PageMatchGroup` (CSS-селекторы, реально проверенные на живой разметке `old.reddit.com` и `dtf.ru`) и правила, матчащие по `extras`-полям (`subreddit`, `hub`, `author`), которые эти селекторы должны заполнять. `pmg-dtf` заполняет `hub` и `author` (имя автора из `<h1>` внутри `.subsite-card__name`, соседнего с блоком бейджа подписки `.user-showcase` — селектор `.subsite-card__name h1` намеренно не заходит внутрь `.user-showcase`); `test-social-dtf-author-entus` матчит по `extras.author = "Никита Ентус"`.
- **`comics/`** — Marvel Fandom wiki (`marvel.fandom.com`): одно доменное правило-сортировщик (в `Comics/Marvel`, с тегами/категорией «Комикс») **и** первый в этих наборах пример `IconRule` (`RULE-13`) — тот же домен, `xpath`-источник `//*[@id="mw-content-text"]/div/aside/section[1]/figure/a/img` (обложка выпуска из инфобокса статьи), реально проверенный на `https://marvel.fandom.com/ru/wiki/Ultimate_Spider-Man_Vol_1_½`.

## Известные ограничения (на момент создания наборов)

- **`domainAliases` не резолвятся движком правил.** `rule-evaluator.ts` не знает о `DomainAlias` — алиасы существуют только как отдельная сущность (UI вкладки «Алиасы» + экспорт/импорт). Поэтому во всех наборах домены в `rules[].condition` и в `domainAliases[].domain_names` продублированы вручную. См. задачу на резолвинг алиасов в правилах в `specs/backlog.md`.
- **`social-extras/` не сработает на живых закладках.** `PageExtractorService`/`PageMatchGroup` — рабочая инфраструктура извлечения `extras` со страницы, но она нигде не вызывается в реальном flow создания закладки (`background.ts` использует только `PageMetaFiller`, который не ходит на страницу; `content.ts` — заглушка). Файл валиден для импорта/экспорта и годится как фикстура на будущее, но правила `test-social-reddit-programming`/`test-social-dtf-games` не найдут совпадения, пока это не подключено. См. задачу на подключение `PageMatchGroup` к реальному flow в `specs/backlog.md`.
- Селектор `h1.redditname a` в `social-extras/` проверен на классической разметке `old.reddit.com`; современный `www.reddit.com` рендерит контент через веб-компоненты (`shreddit-post` и т.п.) с другой структурой DOM — селектор рассчитан именно на `old.reddit.com`-стиль страниц.
