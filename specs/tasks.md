### RULE-3 — Своё действие расширения для создания закладки (обход нативного попапа браузера)
**Priority:** Medium
**Added:** 2026-07-08

Нативный попап браузера «Закладка добавлена» (звёздочка в адресной строке / Ctrl+D) нельзя подавить через `bookmarks` API ни в Chrome, ни в Firefox — хука для этого нет. Обходной путь: добавить собственный триггер сохранения, который создаёт закладку напрямую через `IBookmarkRepository.create()`, — тогда пользователь сохраняет страницу мимо системной звёздочки, и нативный попап вообще не показывается.

**Решение по UI-триггеру** (после того как выяснилось, что `page_action` — Firefox-only API, а в Chrome MV3 `browser_action`/`page_action` объединены в единственный toolbar `action`, второго слота для иконки нет): вместо отдельной кнопки — два экрана внутри уже существующего popup (`entrypoints/popup`), без изменений в манифесте:
- **Экран по умолчанию** («быстрое сохранение») — звёздочка (`IconStar`) в левом верхнем углу; поведение зависит от текущего `Mode`:
  - `Off` — кнопка сохранения не отображается;
  - `Auto` — одна кнопка «Сохранить», клик сразу распределяет закладку по правилам (переиспользует `AutoModeHandler`/`createModeHandler`, как в фоновом flow);
  - `Hint` — путь до папки (иконка папки + редактируемый инпут, предзаполнен предложением от `HintModeHandler`) и кнопка сохранения.
- **Стрелка справа** переключает на второй экран — существующий popup с выбором режима (`PopupHeader` + `PopupModeSelector` + `PopupActions` + `PopupFooter`), без изменений в его логике.

Фактическое создание закладки идёт через сообщение в `background.ts` (а не напрямую из popup), чтобы иметь общий с уже существующим слушателем `bookmarks.onCreated` контекст выполнения: перед вызовом `IBookmarkRepository.create()` выставляется синхронный флаг подавления, проверяемый в начале `onCreated` — это исключает повторную обработку/двойное перемещение только что созданной закладки. Для чтения `url`/`title` активной вкладки из popup нужно разрешение `activeTab` (не `tabs` — не нужен широкий доступ).
