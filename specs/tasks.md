### UI-4 — Бинарный режим ON/OFF и переработка попапа (дерево вместо экрана режимов, поиск вместо второго экрана)
**Priority:** Medium
**Added:** 2026-08-09

Текущая трёхрежимная модель (`Auto`/`Hint`/`Off`) показалась пользователю неинтуитивной. Сводим `Mode` к бинарному `ON`/`OFF`, экран 1 попапа сразу показывает дерево папок с предложенным путём и кнопкой «Сохранить» (без промежуточного экрана и без кнопки «Отмена» — закрывает `UI-3`), экран 2 вместо селектора режима становится поиском по закладкам (`SEARCH-1`), переключатель `ON`/`OFF` — `Switch` в шапке попапа (виден на обоих экранах вместе с кнопкой «Настройки»).

**Объём задачи расширился во втором раунде расспроса**: нативно созданные закладки (звёздочка/Ctrl+D/импорт/синк) вообще перестают автосортироваться — сортировка становится исключительно функцией popup-flow расширения. Это каскадом убирает: `bookmarks.onCreated`/`onImportBegan`-листенеры и флаг `suppressNextCreated` в `background.ts`; весь механизм сообщения popup→background для quick-save (`IQuickSaveService`/`QuickSaveService`/`QuickSaveMessage`) — раз подавлять эхо больше не от чего, попап зовёт `IBookmarkRepository.create()` напрямую; и всю иерархию `IBookmarkModeHandler`/`AutoModeHandler`/`HintModeHandler`/`OffModeHandler`/`BookmarkDecisionStatus`/`createModeHandler`/`BookmarkService` — единственному оставшемуся потребителю (попапу) достаточно `findMatchingRule()` напрямую. Заодно поглощает `UI-2` (цепочка `Mode→Status→View` перестаёт существовать вместе с самими типами), часть `ARCH-10` про `FolderTree.tsx`, и удаляет мёртвый pending-hint код (`PendingHintRepository`/`usePendingHint`/`PopupActions`/`PopupHintConfirm`). Автосортировка нативных закладок не отменяется навсегда — откладывается как отдельная нескоуненная идея, см. `specs/ideas.md`. Пересматривает исходное UI-решение `RULE-3` (два экрана попапа, механизм сообщения) — см. пометку там же. `CLAUDE.md`/`specification.md` обновлены, чтобы отражать новый объём автосортировки. Глубокая спецификация: `specs/tasks/UI-4-binary-mode-popup/`.

### RULE-3 — Своё действие расширения для создания закладки (обход нативного попапа браузера)
**Priority:** Medium
**Added:** 2026-07-08

Нативный попап браузера «Закладка добавлена» (звёздочка в адресной строке / Ctrl+D) нельзя подавить через `bookmarks` API ни в Chrome, ни в Firefox — хука для этого нет. Обходной путь: добавить собственный триггер сохранения, который создаёт закладку напрямую через `IBookmarkRepository.create()`, — тогда пользователь сохраняет страницу мимо системной звёздочки, и нативный попап вообще не показывается.

**Ниже пересматривается `UI-4`** (бинарный `ON`/`OFF` вместо `Auto`/`Hint`/`Off`, второй экран становится поиском вместо селектора режима, а сам механизм создания через сообщение в `background.ts` — прямым вызовом `IBookmarkRepository.create()` из popup, т.к. подавлять эхо `onCreated` больше не от чего) — оставлено как есть для истории исходного решения.

**Решение по UI-триггеру** (после того как выяснилось, что `page_action` — Firefox-only API, а в Chrome MV3 `browser_action`/`page_action` объединены в единственный toolbar `action`, второго слота для иконки нет): вместо отдельной кнопки — два экрана внутри уже существующего popup (`entrypoints/popup`), без изменений в манифесте:
- **Экран по умолчанию** («быстрое сохранение») — звёздочка (`IconStar`) в левом верхнем углу; поведение зависит от текущего `Mode`:
  - `Off` — кнопка сохранения не отображается;
  - `Auto` — одна кнопка «Сохранить», клик сразу распределяет закладку по правилам (переиспользует `AutoModeHandler`/`createModeHandler`, как в фоновом flow);
  - `Hint` — путь до папки (иконка папки + редактируемый инпут, предзаполнен предложением от `HintModeHandler`) и кнопка сохранения.
- **Стрелка справа** переключает на второй экран — существующий popup с выбором режима (`PopupHeader` + `PopupModeSelector` + `PopupActions` + `PopupFooter`), без изменений в его логике.

Фактическое создание закладки идёт через сообщение в `background.ts` (а не напрямую из popup), чтобы иметь общий с уже существующим слушателем `bookmarks.onCreated` контекст выполнения: перед вызовом `IBookmarkRepository.create()` выставляется синхронный флаг подавления, проверяемый в начале `onCreated` — это исключает повторную обработку/двойное перемещение только что созданной закладки. Для чтения `url`/`title` активной вкладки из popup нужно разрешение `activeTab` (не `tabs` — не нужен широкий доступ).

### RULE-5 — Подключить PageExtractorService/PageMatchGroup к реальному flow создания закладки
**Priority:** Medium
**Added:** 2026-07-24

`PageExtractorService`/`PageMatchGroup` (`src/services/PageExtractorService.ts`, `src/lib/page-extractor.ts`) — рабочая инфраструктура извлечения `extras` со страницы через CSS/META/XPath-селекторы, но нигде не вызывается в реальном flow. Подключается только к quick-save-flow (`RULE-3`), через `activeTab` + программную инъекцию `content.ts` (не статический `<all_urls>` матч) — нативный `bookmarks.onCreated` не меняется и помечается комментарием как deprecated (логика продолжает работать без extras, отключать её не стали — единственный механизм, сортирующий закладки, созданные не через popup). Заодно общий `PageMetaFiller.fillPageMeta({url, title})` переиспользуется во всех точках построения `PageMeta` (onCreated + обе quick-save точки) вместо трёх инлайн-копий. Глубокая спецификация: `specs/tasks/RULE-5-page-extractor-quick-save/`.

**Предпосылка про нативный `onCreated` устарела из-за `UI-4`**: та задача убирает нативную автосортировку целиком (переносит идею на будущее, см. `specs/ideas.md`), так что нативный `onCreated` перестаёт быть «единственным механизмом, сортирующим закладки не через popup» — просто потому, что сортировки вне popup больше не будет вообще. По явному решению пользователя `RULE-5` сейчас не пересматривается — основная ценность (протащить `extras` в `PageMeta` для popup-flow) не зависит от нативного потока и не пострадает.
