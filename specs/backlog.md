### RULE-3 — Своё действие расширения для создания закладки (обход нативного попапа браузера)
**Priority:** Medium
**Added:** 2026-07-08

Нативный попап браузера «Закладка добавлена» (звёздочка в адресной строке / Ctrl+D) нельзя подавить через `bookmarks` API ни в Chrome, ни в Firefox — хука для этого нет. Обходной путь: добавить собственное действие расширения (иконка на панели инструментов), которое создаёт закладку напрямую через `IBookmarkRepository.create()`, — тогда пользователь сохраняет страницу через иконку расширения вместо системной звёздочки, и нативный попап вообще не показывается. Нужно спроектировать: обработчик клика по действию расширения; как определяется целевая папка (с учётом текущего `Mode`, аналогично уже существующему flow в `background.ts`); и как это соотносится с уже существующим слушателем `bookmarks.onCreated` — `create()` сам вызовет `onCreated`, нужно не допустить повторной обработки/двойного перемещения.

### UI-1 — Всплывающее уведомление о перемещении закладки в Auto-режиме
**Priority:** Low
**Added:** 2026-07-08

В Auto-режиме показывать тост-уведомление вида «Вкладка сохранена в папку "Соцсети/Reddit"», которое появляется в правом верхнем углу и само пропадает через ~5 секунд. Нерешённый вопрос на момент проектирования: у service worker'а в MV3 нет DOM, так что вариант либо `chrome.notifications` (системное уведомление ОС — просто, но не кастомизируется под тему проекта и не буквально «в правом верхнем углу окна браузера»), либо инжект UI через content script в активную вкладку (кастомизируется, но нужны host permissions и открытая подходящая вкладка). Выбор — отдельное архитектурное решение при старте задачи.
