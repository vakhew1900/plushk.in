### ARCH-2 — Единая точка входа для проверки Mode вместо разрозненных проверок
**Priority:** Low
**Added:** 2026-07-17

Проверки `mode === Mode.X` (или `switch`/тернарники по режиму) сейчас разбросаны по нескольким местам вместо того, чтобы всегда идти через единственный предполагаемый диспетчер — `createModeHandler` (`services/createModeHandler.ts`). Файлы с собственной веткой по `mode`:
- `components/popup/PopupQuickSave.tsx` — цепочка тернарников `mode === Mode.OFF ? ... : mode === Mode.AUTO ? ... : ...` для рендера разного содержимого попапа;
- `hooks/useQuickSave.ts` — `if (mode === Mode.HINT)` перед тем, как считать `suggestedFolder`;
- `components/popup/PopupActions.tsx` — `if (mode !== Mode.HINT || !hint) return null;`;
- `entrypoints/background.ts` — `if (message.mode === Mode.AUTO)` внутри обработчика quick-save сообщения.

Нужно спроектировать, как свести эту логику к одной точке входа (скорее всего опираясь на существующий `createModeHandler`/`IBookmarkModeHandler`, либо явно расширив его контракт под UI-ветвление), не давая каждому месту в коде самостоятельно решать, что означает конкретный `Mode`.
