# plushk.in

*Полка для забытых вещей.*

🇬🇧 [English version](README.md)

**plushk.in** — расширение для браузера (Manifest V3), которое автоматически раскладывает ваши закладки по папкам по заданным вами правилам — вместо плоского, вечно растущего списка «Избранное». Дополнительно расширение умеет извлекать сохранённые страницы в Markdown и отправлять заметки прямо в [Obsidian](https://obsidian.md/) через плагин Local REST API.

## Возможности

- **Сортировка по правилам.** Закладка, сохранённая через попап расширения, сразу попадает в нужную папку — целевая папка определяется сопоставлением условий (домен, заголовок, URL, регулярные выражения, wildcard, произвольные поля...) с метаданными страницы.
- **DSL правил в стиле Elasticsearch.** Правила — это обычные JSON-деревья, комбинирующие `and` / `or` / `not` с листовыми условиями (`term`, `terms`, `regex`, `wildcard`). Достаточно выразительно для вложенных иерархий правил с приоритетами и достаточно просто, чтобы отдать нейросети (см. ниже).
- **Алиасы доменов.** Объединяйте региональные зеркала одного сайта под одним алиасом и ссылайтесь на него в правиле, не перечисляя все домены вручную.
- **Теги и сущности полки.** Присваивайте закладкам теги и категории по типу контента (Книга, Видео, Статья...), при желании — со статусом прогресса (буду читать → читаю → прочитано).
- **Экспорт в Markdown + интеграция с Obsidian.** Извлечение содержимого статьи через `@mozilla/readability` + `turndown` и отправка получившейся заметки в Obsidian.
- **Локальное хранение.** Все правила, теги и метаданные хранятся в IndexedDB на вашей машине — никуда не отправляются, пока вы сами не настроите интеграцию с Obsidian.
- **Импорт/экспорт.** Резервное копирование или передача всей конфигурации правил/тегов/алиасов единым файлом настроек.

## Стек

WXT · React · TypeScript · CSS Modules · Radix UI, хранилище — Dexie.js (IndexedDB).

## Создание правил с помощью ИИ

Условие правила — это небольшое JSON-дерево. Оно достаточно компактное и структурированное, чтобы описать нужное правило обычным языком и попросить нейросеть (Claude, ChatGPT и т.д.) написать за вас JSON — а затем вставить его прямо в JSON-вид редактора правил (вкладка «Правила» в настройках → открыть правило → переключатель JSON). Название, целевая папка и приоритет задаются отдельно в форме — JSON описывает только *условие*.

### С чем сопоставляется условие

Каждое правило проверяется относительно метаданных страницы:

| Поле | Тип | Значение |
|---|---|---|
| `url` | `string` | Полный URL страницы |
| `domain` | `string` | Хост страницы |
| `title` | `string` | `<title>` страницы |
| `description` | `string?` | `<meta name="description">` |
| `author` | `string?` | `<meta name="author">` / OpenGraph |
| `language` | `string?` | `<html lang>` |
| `ogType` | `string?` | `og:type` |
| `tags` | `string[]?` | `<meta name="keywords">` / OpenGraph-теги |
| `publishedAt` | `string?` | Дата публикации статьи |
| `content` | `string?` | Полный извлечённый текст статьи |
| `extras.*` | `string \| string[]` | Любое пользовательское поле |

### Грамматика правил

**Составные узлы** объединяют вложенные правила:

```json
{ "type": "and", "nodes": [ <правило>, <правило>, ... ] }
{ "type": "or",  "nodes": [ <правило>, <правило>, ... ] }
{ "type": "not", "nodes": [ <правило>, <правило>, ... ] }
```

**Листовые узлы** проверяют одно поле:

```json
{ "type": "term",     "field": "domain", "value": "youtube.com" }
{ "type": "terms",    "field": "tags",   "values": ["tutorial", "lecture"] }
{ "type": "regex",    "field": "url",    "pattern": ".*\\/watch\\?v=.*" }
{ "type": "wildcard", "field": "domain", "pattern": "*.edu" }
```

`field` может быть любым ключом из таблицы выше, включая `extras.<ваше_поле>`.

**Пример** — видео на YouTube с тегом или заголовком, указывающим на туториал:

```json
{
  "type": "and",
  "nodes": [
    { "type": "term", "field": "domain", "value": "youtube.com" },
    {
      "type": "or",
      "nodes": [
        { "type": "terms",    "field": "tags",  "values": ["tutorial", "course"] },
        { "type": "wildcard", "field": "title", "pattern": "*tutorial*" }
      ]
    }
  ]
}
```

### Шаблон запроса к нейросети

Скопируйте это в выбранную нейросеть, дописав описание в конце:

```
Ты пишешь условия правил для расширения браузера, сортирующего закладки.
Условие — это JSON-дерево из двух видов узлов:

Составные узлы объединяют вложенные правила:
  { "type": "and", "nodes": [ ... ] }
  { "type": "or",  "nodes": [ ... ] }
  { "type": "not", "nodes": [ ... ] }

Листовые узлы проверяют одно поле:
  { "type": "term",     "field": "<поле>", "value": "<строка>" }
  { "type": "terms",    "field": "<поле>", "values": ["<строка>", ...] }
  { "type": "regex",    "field": "<поле>", "pattern": "<регулярное выражение>" }
  { "type": "wildcard", "field": "<поле>", "pattern": "<маска с * и ?>" }

Доступные поля: url, domain, title, description, author, language,
ogType, tags, publishedAt, content, а также любое кастомное поле
extras.<имя>.

Выведи ТОЛЬКО JSON-дерево условия, без пояснений, соответствующее
следующему запросу:

<опишите здесь, что нужно сопоставлять, например: "страницы репозиториев
GitHub, в заголовке которых упоминается 'rust' или 'go', но не gist'ы">
```

Вставьте получившийся JSON в JSON-вид редактора правил, затем задайте в форме название правила, целевую папку и приоритет.
